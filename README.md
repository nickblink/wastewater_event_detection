# wastewater_event_detection

A minimal, fully public-data companion repo demonstrating the outbreak/peak
detection methods used in our wastewater-based early warning system (EWS)
paper.

**This repo uses different data than the paper.** The paper's primary
analysis used proprietary Biobot Analytics county-level wastewater data under
an academic data-use agreement that cannot be redistributed. To make the
method runnable and inspectable by anyone, this repo instead uses:

- **Wastewater data:** public CDC NWSS ("CDC Wastewater Data for SARS-CoV-2",
  [data.cdc.gov `j9g8-acpt`](https://data.cdc.gov/Public-Health-Surveillance/CDC-Wastewater-Data-for-SARS-CoV-2/j9g8-acpt))
- **Case data:** public Johns Hopkins CSSE county-level confirmed-case time
  series

on a demo subset of **10 US counties**, restricted to **2020–March 2023**
(JHU's active reporting window). Results produced by this repo are
illustrative of the *method* and will not match the paper's results, which
were computed on different (proprietary, more granular) data and a larger set
of locations. See the paper [citation needed] for the actual results.

## What's here

Two detection methods, both applied independently to the wastewater series and
the cases series, for each of the 10 demo counties:

1. **Peak detection** (`R/peak_detection_algorithm.R`,
   `R/peak_classification_metrics.R`): a windowed local-maximum detector
   (`find_simple_peaks`), with wastewater-detected peaks classified as
   true/false positives against case-count-detected peaks (treated as the
   reference). Pure R, runs in seconds.
2. **Bayesian exponential growth** (`R/stan_exponential_growth.R`,
   `stan/modular_outbreak_detection.stan`): a windowed Stan model estimating a
   local growth rate at each time point; an outbreak is flagged when the
   growth rate's posterior credibly exceeds zero. Requires `rstan` or
   `cmdstanr` and a working C++ toolchain, so it's not run by default in CI
   (see setup note below).

## Setup

Requires R (tested on R 4.6). Install dependencies:

```r
Rscript R/00_install_packages.R
```

This installs `readr`, `dplyr`, `tidyr`, `lubridate`, `ggplot2` -- all
pure/precompiled-binary-friendly packages, deliberately avoiding anything that
needs a fresh C/C++ compile if we could avoid it (e.g. we use base R's
`stats::approx()` instead of `zoo::na.approx()`).

The Stan step additionally requires `rstan` (`install.packages("rstan")`) or
[`cmdstanr`](https://mc-stan.org/cmdstanr/), each of which needs a working C++
toolchain. If neither is installed, the main pipeline script below skips that
step automatically and still runs everything else.

## Running the pipeline

```r
Rscript R/run_full_pipeline_10_counties.R
```

This runs, in order: load + clean wastewater data -> load + clean cases data
-> peak detection (WW & cases) -> Stan exponential growth (WW & cases, if
available) -> QC figures. Outputs land in `data/processed/`, `results/`, and
`figures/`.

To run the pieces individually, see the numbered scripts in `R/`.

## Running tests

```r
Rscript tests/run_tests.R
```

Uses a small base-R assertion runner rather than `testthat`, again to avoid a
dependency that needs compilation.

## A note on the demo counties and parameters

The 10 demo counties (`R/00_config.R`) were chosen for having dense wastewater
sample coverage in the 2020-2023 window; `data/raw/nwss_county_subset.csv`
actually contains public data for 793 counties, so you can point
`FIPS_SUBSET` at a different selection to explore more.

The peak-detection window/threshold (`w = 3, threshold = 10,
complete_window_only = TRUE`) matches the convention used for the paper's
county-level analysis. Because NWSS concentration values and case counts are
on very different numeric scales, the `threshold` parameter's practical
effect differs between the two series -- it's a noise floor, not the primary
driver of peak selection, so this is expected.
